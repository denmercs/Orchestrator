# Debrief

A step between Review and PR. It helps the person steering the agents understand the code before it ships, so they don't lose touch with their own codebase.

`debrief-mockup.html` is the target design. Open it in a browser and turn on **show spec notes** for the rules behind each section. The story and code in it are made up.

## Why

AI-written code can ship faster than anyone understands it. In Anthropic's 2026 trial ([summary](https://www.anthropic.com/research/AI-assistance-coding-skills)), developers who handed the work to AI scored lowest on understanding, debugging worst of all. Those who checked their own understanding scored highest. Reading a summary isn't enough. The page asks you to guess, run and trace instead.

## The page

1. **See it run.** A graph of the changed code paths. Pick a scenario (one of the story's tests), guess the ending, and watch the path it takes. A "before (main)" view compares with the old code.
2. **Read the code.** A small code reader with a reading path of up to 5 stops, folding, diff view, go to definition, and notes under the lines they're about.
3. **Expectations.** What you wrote at plan approval, next to what was built, each row linked to the scenario that proves it.
4. **Drift report.** New dependencies, shared modules, public interface changes and files outside the story's scope.
5. **Done.** Marks the debrief done, and the plugin opens the PR.

## Built by a script

The page is generated by a script, so the same commit and notes give the same file every time.

- **Script, from git and the tests:** header, files, code, highlighting, folding, go to definition, drift report, scenarios (per-test V8 coverage), graph, page. One fixed template with the data embedded as sorted JSON. Works offline.
- **Agent, in `.harness/debrief/notes.json` only:** the summary, the stops, Decision / Watch / Note text, graph box labels and the "Built" column. The script validates every field against real lines, branches and scenarios. A missing or invalid file still renders the rest and lists what failed.
- **v1 limit:** coverage shows which lines a scenario ran, not their order or values. Step-by-step playback with state needs instrumentation and comes later.

## Never in a repo

- The page lives in `~/.orchestrator/debriefs/<repo>/<story>/`, outside the repo.
- Agents write only the notes, in `.harness/`, which is excluded from git and unstaged by the plugin's commit.
- Before pushing, the plugin refuses to open the PR if any commit on the branch touches `.harness/` or a debrief file.

## Cleanup

- **On merge:** delete the story's debrief folder, next to the existing workspace archive.
- **PR closed but the story only blocked:** keep it. Delete it when the story is dropped.
- **On plugin start:** sweep folders whose story is merged, gone, or older than 14 days.
- **Never deleted:** the understanding record, `~/.orchestrator/understanding/<repo>/`, which holds short notes and paths, not code.
